# 독서 기록

모바일 하단 가운데 **독서**, PC 상단 **독서 기록**을 누르면 현재 화면에서 입력창이 열린다. 오늘 화면과 캘린더의 일정 카드에서도 해당 도서를 선택한 상태로 열 수 있다. 이 창은 도서 진도만 받는다. 영어 학습 시간은 **영어학습**의 타이머가 자동으로 기록한다.

- 기록 가능한 책이 한 권이면 자동 선택한다. 여러 권이면 오늘 일정이 있는 책부터 표시하고 직접 선택한다.
- 마지막으로 읽은 페이지를 입력하면 기존 진도와의 차이를 보여준다. 예정 분량을 실제 학습량으로 자동 입력하지 않는다.
- 학습 날짜는 계획의 시간대 기준 오늘이다. **추가 입력**에서 날짜, 학습 시간, 메모, 복습을 설정한다.
- 복습은 페이지 범위를 기록하며 읽은 진도를 늘리지 않는다. 완독한 책도 복습할 수 있다.
- 계획이 없거나 일시 정지되었거나 보관된 책은 기록 대상에서 제외한다. 기존 상세 화면에서 준비/설정을 진행한다.
- 기록할 책이 하나도 없으면 서재로 안내하고, 영어 학습 시간은 영어학습에서 자동 기록된다는 안내와 링크를 함께 보여준다.
- 저장 성공 시 입력창을 닫고 결과를 알린다. 현재 화면의 진도, 일정, 통계를 다시 불러온다. 일정 조정이 대기 중인 경우에도 기록 저장과 구분해서 안내한다.
- 통신 오류로 저장 결과가 불명확하면 도서 변경과 닫기를 막고, 같은 멱등성 키로 재확인한다. 버전 충돌 시에는 최신 기록을 불러온 뒤 다시 입력한다.

## 구현

`QuickRecordProvider`는 인증 사용자별로 분리되며 네이티브 `dialog`의 모달 동작과 포커스 복원을 사용한다. `visualViewport` 변화에 맞춰 하단 위치와 최대 높이를 조절하고 저장 버튼은 스크롤 영역 하단에 고정한다. `ProgressForm`의 compact 모드를 사용하여 기존 진도 API의 검증, 중복 방지와 일정 재계산을 재사용한다.

## 검증 (2026-09-13)

- 단위/API/스케줄러 테스트 151개, web 타입 검사, 린트, 전체 프로덕션 빌드 통과.
- 390×844 모바일, 390×450의 짧은 화면, 1280×900 데스크톱 브라우저에서 입력창 확인.
- 별도 로컬 테스트 계정으로 15쪽 기록 → 5쪽 추가 기록 → 10쪽 복습/5분 저장 확인. 최종 읽은 진도는 20쪽, 복습은 별도 이벤트로 저장됨.
- 첫 저장 응답만 503으로 대체하는 브라우저 검증에서 같은 요청 본문으로 재시도하고 이벤트가 중복 생성되지 않는 것 확인. 이때 Escape/닫기/도서 변경이 차단됨.
- 409 응답을 주입하여 재입력 차단 및 최신 기록 불러오기 후 입력 가능 상태 회복 확인.
- 도서 없음 안내, 한 권 자동 선택, 여러 권 선택, 일정 카드에서 대상 도서 지정, 저장 후 일정 갱신, 재열기, Escape 닫기 확인. 페이지 JavaScript 오류 없음.
- 실제 휴대폰 OS 키보드와 iOS Safari는 직접 검증하지 못함. 짧은 뷰포트에서 저장 버튼 접근성은 확인함.
