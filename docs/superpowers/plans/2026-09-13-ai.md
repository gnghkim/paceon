# Phase 6 AI Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Existing PRD Phase 6 and user instruction authorize implementation; keep the new phase uncommitted for review.

**Goal:** Offer durable background book difficulty/time estimates and short evidence-based coaching without changing deterministic schedules.

**Architecture:** Authenticated Next API builds an owned, bounded context snapshot and enqueues an RLS job. FastAPI worker polls PostgreSQL through service-role-only claim/finish RPCs, calls OpenAI Responses structured outputs, validates results, and stores provenance. Detail UI polls owned jobs and shows confidence, basis, stale results and explicit unavailable/failure states. No PDF parsing or mastery scoring in this phase.

**Tech Stack:** Next/React, Zod shared contracts, PostgreSQL queue with leases, Python FastAPI/Pydantic and standard-library HTTP.

## Contract (all field names exact)

Kinds `BOOK_ANALYSIS`, `COACH`. Job states `PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`.

Input JSON (built only by server API): `{schemaVersion:1, kind, book:{title:string,authors:string[],totalPages:integer,description:string}, outline:string, facts:{today:string,completedPages:integer,remainingPages:integer,progressPercent:integer,planMode:string|null,forecastDate:string|null,targetDate:string|null,replanRequired:boolean,recentLearningPages:integer,recentLearningMinutes:integer,validTimedSamples:integer}, sourceRevision:string}`. Title<=500, authors<=20×200, description<=4000, outline<=12000. facts from last7 calendar days, only active LEARNING; no memo/email/token sent. sourceRevision SHA256 of canonical full context excluding sourceRevision; changes make prior result stale. Outline optional pasted table of contents; metadata-only analysis must disclose limited evidence. No copyrighted source retrieval.

BOOK_ANALYSIS output strict JSON: `{difficulty:'EASY'|'MODERATE'|'CHALLENGING',estimatedMinutes:integer1..10000000,importance:'LOW'|'MEDIUM'|'HIGH',confidence:number0..1,summary:string1..600,reasons:string[1..4]each1..300}`. Whole-book estimated minutes, advisory only, never auto-written to plan speed or units.

COACH output strict JSON: `{summary:string1..800,suggestions:string[1..3]each1..300,confidence:number0..1}`. Two to four Korean sentences, no invented trend/mastery, no schedule edits or novel numeric calculations. Both outputs rendered as text, marked AI estimates.

DB `ai_jobs`: id uuid, user_id uuid cascade auth.users, resource_id uuid owner-composite FK cascade, kind text, status text, input jsonb, source_revision text, result jsonb nullable, model text nullable, provider_response_id text nullable, input_tokens integer nullable, output_tokens integer nullable, error_code text nullable, attempts integer default0, lease_token uuid nullable, lease_expires_at timestamptz nullable, created_at/updated_at timestamptz. Unique active job(resource_id,kind) partial PENDING/PROCESSING prevents duplicate spend. User SELECT only; enqueue function SECURITY DEFINER derives auth.uid, checks own BOOK and peruser pending/processing <=5, input size/shape/kind/revision; same completed revision returns existing job and refreshes updated_at; enqueue always reuses completed same revision; failed can retry new job. In-progress samekind returns existing job (UI marks stale if snapshot differs).

RPC `enqueue_ai_job(p_resource_id uuid,p_kind text,p_input jsonb,p_source_revision text) returns uuid`; auth user execute only. `claim_ai_job() returns jsonb` service-role only, skiplocked, 120-second expired leases retried, max3attempts then FAILED/WORKER_TIMEOUT; return claimed row or null. `finish_ai_job(p_job_id uuid,p_lease_token uuid,p_result jsonb,p_model text,p_provider_response_id text,p_input_tokens integer,p_output_tokens integer,p_error_code text) returns boolean` service-role only; matching live lease required, writes COMPLETED or FAILED, clears lease. Failed result must not contain provider messages/secrets. Never grant browser writes to result/status.

Web GET `/api/resources/books/[id]/ai` -> `{available:boolean,sourceRevision:string,jobs:AiJobView[]}` mostrecent10 per kind ordered by latest activity, sanitized view excludes input/lease/tokens/provider_response_id; exposes id,kind,status,result,model,errorCode,sourceRevision,createdAt,updatedAt. POST body `{kind,outline?:string}` ->202 `{job:AiJobView,sourceRevision}`; samecompleted200 optional; configured unavailable503 safe Korean. Auth401, foreign404,invalid400,queuefull429. Server-only `AI_ENABLED=true` gate. Each GET/POST builds current context; GET uses most recent BOOK_ANALYSIS input outline for revision; COACH uses outline empty. Return perkind `sourceRevisions:{BOOK_ANALYSIS:string,COACH:string}` in GET to correctly mark stale. No automatic enqueue on GET. UI explicit analysis/coach actions, background status polling with abort, prior results retained, retry failed samekind, timeout never claims success. UI may edit outline for analysis.

Worker env: `AI_ENABLED=true`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `OPENAI_API_KEY`, `OPENAI_MODEL` required (no unverified default), optional `AI_POLL_SECONDS` default3. OpenAI fixed https://api.openai.com/v1/responses, timeout45, store:false, no tools, strict text.format json_schema. Health liveness unchanged. Background starts only if configured; authenticated DB claim/finish are the only job access. Never log credentials/providerbody/input. OpenAI output size bounded and Pydantic validated before persistence; refusal/incomplete/invalid/schema/provider errors -> sanitized FAILED code. Consumer HTTP calls bounded, stopcleanly on shutdown, leases prevent stale writes. Metadata-only insufficient evidence handled prompt confidence guidance, no fabricated fallback result.
