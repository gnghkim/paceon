# LR3 스피킹·쉐도잉 구현

승인된 LEARNING_ROOM_SPEC의 LR3를 구현한다. 기존 학습룸과 단일 세션 타이머를 재사용한다.

## 사용자 흐름

- 학습룸에서 짧은 영어 문장 생성 → AI 음성 듣기 → 따라 읽기 → 녹음 확인 → 명시적 분석.
- 녹음은 최대 60초·10MiB. 권한 요청·업로드·AI 대기 시간을 학습 시간에서 제외한다.
- YouTube는 5–30초 구간을 듣고 영상을 멈춘 뒤 녹음한다. 기준 문장이 없으면 자유 발화로 분석한다.
- 원본 인식문과 수정문을 보존하고 단어 차이를 후보로 표시한다. 발음 점수는 제공하지 않는다.
- 일시정지·종료·탭 숨김 시 마이크를 닫고 미분석 녹음을 보존한다.

## 구현 계약

비공개 Storage 버킷 `learning-audio`. `learning_speech` 소유자 조회 전용 테이블:
`id,user_id,workspace_id,session_id,kind(PROMPT|RECORDING),status(UPLOADING|QUEUED|RUNNING|READY|FAILED|DELETED),reference_text,original_text,edited_text,feedback,json input,storage_path,mime_type,file_size,content_sha256,duration_seconds,keep_audio,expires_at,error_code,attempts,lease_token,lease_expires_at,created_at,updated_at`.
공개 응답은 input·스토리지 경로·해시·lease를 제외한다. feedback은 기존 LearningOutput 구조를 사용한다. PROMPT 완료 시 reference_text에 영어 문장, feedback.summary에 한국어 뜻을 저장한다.

- `learning_speech_command(p_command)`:
  - `SPEECH_TICK`: requestId,sessionId,deviceId,generation,playing(bool). 기존 세션 lease를 검증하고 실제 재생·녹음 시간만 반영한다. 반환값은 `{session}`.
  - `PROMPT`: requestId,id,workspaceId,level(EASY|MEDIUM),topic(최대200자). QUEUED 생성. 동일 requestId 재시도는 재사용.
  - `EDIT`: requestId,id,text(최대8000자). 원본을 보존하며 수정본만 변경.
  - `DELETE`: requestId,id. 즉시 tombstone, 늦은 worker 완료를 무시하고 비동기 파일 삭제.
  - `KEEP`: requestId,id,keep(bool). 기본 음성 보관30일.
  - `RETRY`: requestId,id. 실패한 요청을 제한 내 재시도.
- `begin_speech_upload(p_id,p_workspace_id,p_session_id,p_reference_text,p_mime_type,p_file_size,p_content_sha256)` → row. 경로는 `{userId}/{id}/recording`으로 고정.
- `queue_speech_recording(p_id)` → row. Storage 객체 확인 후 QUEUED. 이 호출은 분석 동의 이후에만 수행.
- service only `claim_speech_job()` → row or null; `finish_speech_job(p_job_id,p_lease_token,p_output,p_error_code)` → bool. output: `{referenceText,originalText,feedback,storagePath,mimeType,durationSeconds}`. PROMPT 경로 `{userId}/{id}/sample.mp3`. RECORDING 경로 유지.
- service only `speech_cleanup_candidates()` → `{id,storage_path}` 배열; `finish_speech_cleanup(p_id)`는 파일 경로를 비우고 keep되지 않은 만료 음성의 삭제를 기록한다. DELETED 메타데이터는 되살리지 않는다.

API: GET `/api/learning/speech?workspaceId=...` → `{items,enabled}`; POST `/api/learning/speech/commands` → `{item}`; POST `/api/learning/speech/upload` raw audio + headers `x-speech-id,x-workspace-id,x-session-id,x-reference-text`(URI encoded) → `{item}`. GET `/api/learning/speech/[id]/audio` → 비공개 오디오 응답(소유자 인증, no-store).

서비스에서 모델 기본값은 `gpt-4o-mini-transcribe`, `gpt-4o-mini-tts`, voice `marin`. 문장·피드백은 기존 OPENAI_MODEL을 사용한다. 서버에서 실제 오디오 형식·길이·무음을 검증한 후 분석한다. OpenAI 키는 worker에만 둔다.

## 작업과 검증

1. DB/RLS/Storage/작업 lease와 quota, 삭제·만료 경합: pgTAP.
2. Worker 음성 생성·검증·전사·피드백·정리: 제한과 실패/재시도 단위 테스트.
3. API 소유권·입력·업로드 제한: Node 테스트.
4. UI 녹음 수명주기·타이머·쉐도잉·재개: 타입검사와 브라우저 테스트.
5. 실제 비사용자 샘플 음성으로 provider 연결 확인, 전체 회귀 검사 및 문서 갱신.
