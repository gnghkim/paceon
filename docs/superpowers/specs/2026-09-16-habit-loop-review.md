# 습관화 관점 시스템 검토와 개선안

작성일: 2026-09-16 · 기준 커밋: `85fec7d`

## 1. 목적과 범위

PaceOn을 만드는 목적은 독서와 영어학습을 **습관화**하는 것이다. 학습을 계획하고, 실제로 공부하고, 기록하면서 루틴을 만든다. 이 문서는 그 목적에 비추어 현재 구현을 검토하고, 루틴 형성에 필요한 기능과 UX/UI 개선안을 우선순위와 함께 정리한다.

**포함**

- 오늘·캘린더·기록·계획·통계·영어학습의 루틴 관점 검토.
- 습관 루프(신호 → 행동 → 기록 → 피드백)에서 빠진 부분.
- 화면 구성, 문구, 이름 일관성.

**제외**

- 스케줄러 알고리즘, 재계획 정책, AI 프롬프트의 변경.
- 데이터 무결성·동시성·멱등성 설계. 이 부분은 이미 충분하다.
- 리딩(RC) 영역 추가, 강의·Unit 자료 등 PRD의 P1·P2 범위.

## 2. 현재 구조 (확인한 사실)

### 잘 되어 있는 것

- 간편 기록창은 한 권이면 자동 선택하고 페이지 하나만 받는다. 날짜·시간·메모·복습은 접혀 있다. 습관용 입력으로 적절하다.
- 기록 저장 즉시 재계획이 돌고, 예상 완독일 전후를 보여준다.
- 연속일은 오늘 미기록이면 "어제까지"로 표기해 0으로 떨어뜨리지 않는다(`apps/web/src/lib/study-heatmap.ts` `computeStreak`).
- 잔디는 시간 미입력 기록도 level 1로 잡는다. "기록만 해도 잔디가 찍힌다"가 성립한다.
- 영어학습 타이머는 화면 숨김·1분 무활동에 멈춘다. 시간 통계가 정직하다.
- 통계와 잔디가 도서 기록과 영어학습 시간을 한 기준으로 센다.
- 기록의 멱등성, 정정 이력, 시간대 처리, 버전 충돌 처리가 갖춰져 있다.

## 3. 개선안

우선순위 P0(루틴이 성립하려면 필요) → P1(루틴을 오래 유지) → P2(마찰 제거·정리) 순이다. 각 항목은 위 표의 F·U 번호를 참조한다.

### P0-1. 오늘 세션 완료 상태 (F1)

세션 카드가 `session.status`를 읽어 세 가지 상태를 표시한다.

- **PLANNED**: 지금과 같다. "학습 기록" 버튼.
- **IN_PROGRESS**: 오늘 일부만 읽었다. "N쪽 남음"과 함께 기록 버튼 유지. `completedThroughPage`와 `end_page` 차이로 계산한다.
- **COMPLETED**: 체크 표시, 흐린 배경, "완료 · N쪽". 버튼은 "추가 기록"으로 바꾼다. 초과해 읽은 경우도 이 상태다.

오늘 세션이 모두 COMPLETED이면 "오늘의 분량" 헤더 아래에 "오늘 분량을 다 읽었어요" 한 줄을 보여준다. 애니메이션·배지·점수는 넣지 않는다(DESIGN §2.1 Calm).

데이터는 이미 `WorkspaceData.sessions`에 있으므로 API 변경이 없다.

### P0-2. 오늘 화면에 영어학습 카드 (F4)

"오늘의 분량" 섹션 아래(또는 세션이 없으면 그 자리)에 영어학습 카드를 하나 둔다.

- 내용: 오늘 영어학습 누적 분(`StatisticsData.days[today].learningMinutes`), 최근 룸 이어하기 하나(`resumeWorkspaces(list, 1)`), "새로 시작" 링크(`/learn`).
- 하루 목표 분(기본 10분)을 `learner_profiles`에 저장하고 "오늘 7/10분"으로 표시한다. 목표를 못 채워도 경고하지 않는다. 목표 설정은 설정 페이지에 둔다.
- 오늘 기록이 0분이면 "한 문장부터 시작해요" 정도의 안내만 둔다.

이 카드가 들어가면 U3의 "꾸준함을 위한 여유" 카드와 "오늘 읽은 진도 남기기" 섹션은 뺀다.

필요한 변경: `learner_profiles`에 `daily_learning_minutes` 컬럼(선택, 기본 NULL), 설정 페이지 입력 하나, 오늘 화면에서 `/api/learning/workspaces` 한 번 더 조회.

### P0-3. 밀린 분량 정리와 안내 (F2, F3)

앱을 열 때(오늘 화면 로드 시) 지난 날짜의 PLANNED 세션이 있으면 기록 없이 재계획을 한 번 돌린다.

- 방법: 기존 `progress` 함수에 `kind='REPLAN'`을 현재 설정 그대로 보내는 "정리" 호출을 추가한다. 세션 상태는 `progress_replanning.sql:159`가 이미 SKIPPED로 바꾸므로 새 SQL은 필요 없다. 호출 시점만 추가한다.
- 트리거 조건: `sessions` 중 `study_date < today && status === 'PLANNED'`이 하나라도 있는 책. 하루에 한 번만 시도한다(로컬 저장소에 마지막 정리 날짜 기록).
- 안내: 재계획 결과의 `reasons`를 써서 오늘 화면 상단에 "어제 못 읽은 20쪽을 앞으로 나눴어요 · 예상 완독 10월 3일" 한 줄. 닫기 가능. 비난하는 문구는 쓰지 않는다.
- 충돌이 나면 기존처럼 `replan_required`가 켜지고 "계획을 다시 정해 주세요" 링크를 보여준다.

캘린더는 지난 날짜의 COMPLETED와 SKIPPED를 구분해 그린다. COMPLETED는 체크, SKIPPED는 흐리게 표시하고 숨기지 않는다. 오늘 화면의 세션 카드 상태(P0-1)와 같은 표현을 쓴다.

Ahead/Behind는 도서 상세의 예상 완독 카드에 "목표보다 N일 빠름/늦음"으로만 표시한다. 목표일이 없으면 표시하지 않는다.

### P1-1. 계획 수정 상시 노출 (F5, F6, F7)

도서 상세의 기록 폼과 별도로 "계획 수정" 카드를 둔다.

- 하루 분량, 모드, 목표일 변경: 기존 REPLAN 요청을 그대로 쓴다. UI에서 `replan_required` 조건만 뺀다.
- 일시 정지·재개: `plans.status`를 PAUSED/ACTIVE로 바꾸는 명령을 추가한다. PAUSED 동안은 오늘·캘린더·간편 기록에서 빠진다(간편 기록의 `recordableBooks`는 이미 PAUSED를 제외한다). 재개 시 재계획을 한 번 돌린다.
- 보관: `resources.status`를 ARCHIVED로 바꾼다. 서재 필터에 "보관"을 추가한다.
- 가용 요일·시간·시간대 수정: 설정 페이지에 "학습 시간" 섹션을 추가한다. 저장 시 ACTIVE 계획 전부를 새 가용 시간으로 재계획하고, 충돌이 나면 저장을 막고 어느 책이 걸리는지 보여준다. DB의 "Shared settings changed" 검사는 유지하고, 설정 저장용 함수를 따로 만든다.

### P1-2. 이번 주 요약 (F9)

오늘 화면 사이드의 잔디 카드 위에 "이번 주" 줄을 추가한다. "월 화 수 목 금 토 일" 일곱 칸에 학습한 날을 채우고 "이번 주 4일"로 요약한다. 데이터는 잔디용 통계 응답에서 이미 온다. 새 API 없음.

### P1-3. 설치형 PWA와 알림 (F8)

- 1단계: `manifest.webmanifest`, 아이콘, `display: standalone`. 오프라인 캐시는 넣지 않는다(초안 보관은 이미 로컬 저장소가 담당).
- 2단계: 설정 페이지에 "매일 알림" 시각 하나. 브라우저 Web Push로 "오늘 20쪽 · 영어 10분" 한 줄. 서버 발송은 Supabase cron 또는 Worker 스케줄로 한다. 알림을 안 켜도 모든 기능이 동작해야 한다.

### P1-4. 영어 표현 저장과 오늘의 복습 (F10)

LEARNING_ROOM_SPEC.md §9를 따른다. 이 문서에서는 범위만 정한다.

- AI 첨삭·정리 결과에서 표현을 골라 저장한다. 자동 저장은 하지 않는다.
- 오늘 화면의 영어 카드(P0-2)에 "복습 3개"를 붙인다. 밀린 개수는 경고하지 않는다.
- 복습 답변은 학습 시간에 포함한다(스펙 §7.3).

### P2-1. 이름과 버튼 정리 (U1, U2, U3, U8)

- 화면 이름을 **서재**로 통일한다. 내비, 제목, 헤더 fallback, 안내문 모두.
- 추가 버튼은 "책 추가" 하나로 통일하고, 데스크톱에서는 사이드바에만 둔다. 헤더의 "자료 추가"는 뺀다. 오늘 헤더의 버튼은 첫 자료가 없을 때만 보여준다.
- 헤더 오른쪽의 "나만의 속도로, 꾸준하게" 문구는 뺀다.
- 통계 헤더 문구를 "책과 영어학습에 남긴 기록을 모았어요"로 바꾼다.

### P2-2. 도서 상세 순서 (U4)

진도 카드 → 기록 폼 → 다가오는 일정 → 계획 수정 → AI 인사이트 → PDF → 이력 순으로 바꾼다. 매일 쓰는 것이 위, 가끔 쓰는 것이 아래다.

### P2-3. 계획 폼 마찰 줄이기 (U5)

- 시간대: 브라우저 값을 자동으로 쓰고 폼에서 숨긴다. 설정 페이지에서만 바꾼다.
- 쪽당 시간: "빠름 0.5분 / 보통 1분 / 느림 2분" 세 선택지와 "직접 입력"으로 바꾼다. 소수 셋째 자리 입력은 직접 입력에서만 허용한다.
- 기록이 3개 이상 쌓이면 통계의 실측 속도를 폼 기본값으로 제안한다(`estimateReadingSpeed`는 이미 있다).

### P2-4. 잔디 기준 보완 (U6)

시간 미입력 도서 기록은 페이지 수로 대체 추정한다. 계획의 `minutesPerPage`(없으면 1분/쪽)를 곱해 잔디 level에만 쓴다. 통계의 "기록된 시간"에는 넣지 않는다. 문서에 "추정"임을 적는다.

### P2-5. 그 밖의 정리 (U7, U9, U10)

- 모바일 하단 내비: 현재 구성을 유지한다. 캘린더는 오늘 화면의 "다가오는 학습" 섹션 제목을 링크로 만들어 한 번 더 진입로를 둔다.
- 다크 모드: `prefers-color-scheme: dark`에 토큰만 재정의한다. 수동 전환은 넣지 않는다.
- 타이머 문구: 사용자용 세 가지("학습 중", "잠시 멈춤", "끝냄")로 줄이고, 동기화·기기 상태는 문제가 있을 때만 보조 문구로 보여준다.

| 4 | P2-1 이름·버튼 정리 | 작고 눈에 띈다. P0 작업과 같은 파일을 건드리므로 함께 한다 |
| 5 | P1-1 계획 수정 | 생활 변화에 맞춰 계획을 살린다 |
| 6 | P1-2 이번 주 요약 | 새 API 없이 끝난다 |
| 7 | P2-2, P2-3 | 첫 계획과 매일 기록의 마찰 제거 |
| 8 | P1-3 PWA·알림 | 배포 환경(HTTPS, 발송 주체) 확인 후 |
| 9 | P1-4 영어 복습 | LR4 스펙과 함께 별도 계획으로 |

각 항목은 `docs/superpowers/plans/`에 개별 구현 계획을 쓰고 진행한다.

## 5. 수용 기준

- 오늘 분량을 기록하면 새로고침 없이 카드가 완료 상태로 바뀐다.
- 어제 세션을 기록하지 않고 오늘 앱을 열면, 어제 세션은 SKIPPED가 되고 남은 분량이 내일 이후로 재배정되며 오늘 화면에 그 사실이 한 줄로 보인다.
- 오늘 화면에서 영어학습 룸으로 두 번 이내 탭으로 들어간다.
- 가용 시간과 하루 분량을 충돌 없이 언제든 바꿀 수 있고, 바꾼 즉시 캘린더에 반영된다.
- 이름 변경 후 "라이브러리"와 "자료 추가" 문자열이 화면에 남지 않는다.
- 기존 테스트(`pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`)가 통과한다.
