# 보편 학습 자료 설계 검토

작성일: 2026-09-19

온라인 강의, 학습지, 문제집 같은 자료를 등록하면 학습 일정이 만들어지고, 학습한 내용을 기록하고 관리하는 방향을 검토한다. 앞선 [학습 과학 검토](2026-09-19-learning-science-and-generalization.md) 4절의 G2와 G3를 코드 수준까지 내려 본 것이다. 구현 문서가 아니라 결정을 위한 검토다.

> **갱신(같은 날).** 실제 예시 두 개를 받고 다시 보았다. 10절이 7절의 순서를 대신한다. 요점은 이렇다. 두 예시 모두 **챕터가 있는 자료**이고, 챕터를 1급 개념으로 올리면 교재와 강의가 같은 모양이 된다. 그래서 "고른 분량형 먼저, 목차형 나중"이 아니라 **"챕터가 있는 자료" 하나로 연다.**

## 1. 결론

**할 수 있고, 생각보다 가깝다. 다만 자료가 두 모양으로 갈리고, 그중 하나만 쉽다.**

| 모양 | 예 | 지금 엔진으로 | 필요한 일 |
| --- | --- | --- | --- |
| **고른 분량형** | 책, 학습지, 문제집, 교재 | 그대로 된다 | "쪽"이라는 이름을 단위 이름으로 바꾸는 일 |
| **목차형** | 온라인 강의, 회차가 다른 커리큘럼 | 안 된다 | 항목마다 길이가 다른 것을 일정 엔진이 알게 하는 일 |

학습지와 문제집은 책과 구조가 같다. 분량이 N개 있고, 하나하나의 무게가 비슷하고, 앞에서부터 순서대로 한다. 강의는 다르다. 1강이 12분이고 2강이 58분이면 "하루 2강"은 어떤 날은 가볍고 어떤 날은 넘친다.

그래서 **학습지·문제집을 먼저 열고, 강의는 그다음**을 권한다. 앞쪽은 이름을 푸는 일이고 뒤쪽은 엔진을 고치는 일이다.

## 2. 지금 코드가 어디까지 와 있나

확인한 사실만 적는다.

**이미 준비된 것**

- `resource_type`에 BOOK, PDF, COURSE, VIDEO, CUSTOM이 있고 `workload_unit`에 PAGE, UNIT, MINUTE이 있다. `resources.total_units`도 있다.
- `schedule_sessions.planned_workload`와 `progress_events.completed_workload`는 단위 중립인 숫자다.
- `resource_units` 표가 있다. 제목, 순서, 예상 시간, 난이도, 중요도, 상위 단위, 단위 종류(CHAPTER, LECTURE 등)를 가진다. 강의 목차를 담기에 맞는 모양이다.
- `learner_profiles`에 `units_per_hour`와 `workload_multiplier`가 있다. 쪽이 아닌 단위의 속도를 배울 자리다.
- **일정 엔진의 계산은 단위를 모른다.** `packages/scheduler`는 192줄이고, 정수 분량을 날짜에 나눠 담는 산수다. 변수 이름이 `totalPages`, `minutesPerPage`일 뿐이다. 테스트 52개가 안전망이다.
- 독서 회상 카드는 이미 자료(`resource_id`)에 묶여 있어 책이 아닌 자료에도 그대로 쓸 수 있다.
- YouTube 재생목록을 계정에서 읽어 오는 기능이 영어학습 쪽에 있다.

**묶여 있는 것**

| 곳 | 내용 |
| --- | --- |
| 자료 생성 | `packages/books` 하나뿐이고 `type: 'BOOK'`, `workload_unit: 'PAGE'`로 고정한다 |
| 진도 저장 | SQL 함수 `submit_book_progress`가 `type <> 'BOOK'`이면 거절한다 |
| 표 제약 | `start_page`, `end_page` 칼럼이 있고 `planned_workload = end_page - start_page + 1`을 강제한다 |
| 통계 | BOOK이면서 PAGE인 자료만 집계한다 |
| 화면 문구 | "쪽"이 25개 파일 62줄에 박혀 있다. 기록 창, 통계, 도서 상세, 계획 폼 순으로 많다 |
| 목차 | `resource_units`는 PDF 가져오기만 쓰고(목차 저장), 아무도 읽지 않는다 |
| 속도 | `units_per_hour`와 `workload_multiplier`는 아무도 쓰지 않는다 |
| 엔진 가정 | **단위당 시간이 모두 같다.** 하루 분량은 `가용 분 ÷ 단위당 분`으로 계산한다 |

마지막 줄이 강의를 막는 단 하나의 진짜 장벽이다. 나머지는 이름과 문지기다.

## 3. 자료의 모양

### 3.1 고른 분량형

정의: 분량이 1부터 N까지 있고, 하나의 무게가 비슷하고, 순서대로 하며, 진도를 "N번까지 했다"로 말할 수 있다.

| 자료 | 단위 | 비고 |
| --- | --- | --- |
| 책, 교재, PDF | 쪽 | 지금 그대로 |
| 학습지 | 쪽 또는 장 | 주 단위로 새 분량이 오는 경우 총량을 늘리면 된다 |
| 문제집 | 문항 또는 쪽 | 맞고 틀린 것을 남기려면 6절 참고 |
| 강의(간이) | 강 | 길이를 모를 때. "40강, 평균 30분"으로 등록 |

사용자가 등록할 때 **단위 이름**을 고른다. 쪽, 문항, 장, 강, 회 중 하나이거나 직접 적는다. 엔진과 DB에는 숫자만 간다.

마지막 줄이 중요하다. 강의도 목차를 입력하기 귀찮으면 고른 분량형으로 등록할 수 있어야 한다. 정확도는 떨어지지만 등록이 10초에 끝난다. **등록이 귀찮으면 아무도 쓰지 않는다.**

### 3.2 목차형

정의: 항목이 순서대로 있고 **항목마다 예상 시간이 다르다.** 진도는 여전히 "k번째까지 했다"다.

`resource_units`가 원본이 된다. 일정은 항목을 통째로 날짜에 담는다. 하루 가용 시간이 60분이면 12분짜리와 40분짜리를 담고, 58분짜리는 다음 날로 넘긴다.

엔진에 필요한 변화는 하나다. 지금은 `하루 분량 = floor(가용 분 ÷ 단위당 분)`인데, 이것을 **"다음 항목의 시간을 누적해 가용 분을 넘기 전까지"**로 바꾼다. 고른 분량형은 모든 항목의 시간이 같은 특수한 경우가 되므로 같은 코드로 돈다. 기존 테스트 52개가 그대로 통과해야 하고, 그것이 회귀 검사다.

풀어야 할 정책이 세 가지 있다.

- **하루에 안 들어가는 긴 항목.** 가용 시간이 30분인데 58분짜리 강의가 있다. 선택지는 그 항목만 넘침을 허용하는 것, 가장 여유 있는 요일로 보내는 것, 충돌로 알리는 것이다. **넘침 허용**을 권한다. 강의 하나를 이틀에 나눠 듣게 계획하는 것은 실제 행동과 맞지 않고, 충돌로 막으면 등록 자체가 실패한다.
- **실제 시간은 영상 길이와 다르다.** 1.5배속이면 짧아지고 멈춰 가며 필기하면 길어진다. 등록할 때 배수를 하나 받는다(기본 1.0). 기록에 실제 시간이 쌓이면 책의 속도 추정과 같은 방식으로 배수를 배운다. `workload_multiplier`가 이 자리다.
- **순서를 건너뛰는 수강.** 지금 모델은 "k번째까지"만 안다. 5강을 먼저 듣는 경우는 다루지 않는다. 책도 같은 제약으로 잘 돌아가고 있으므로 첫 버전에서는 받아들이고, 필요가 확인되면 항목별 완료로 넓힌다.

## 4. 등록: 입력 비용이 가장 큰 위험

일정 엔진보다 이쪽이 제품의 성패를 가른다. 40강짜리 목차를 손으로 치게 하면 끝이다.

| 방법 | 대상 | 비용 | 평가 |
| --- | --- | --- | --- |
| 제목, 총 분량, 단위 이름 | 학습지, 문제집, 강의(간이) | 10초 | **첫 단계. 반드시 있어야 한다** |
| 목차 붙여넣기 | 강의 | 1분 | 강의 페이지의 커리큘럼을 복사해 붙이면 "1강 OT 12:30" 같은 줄에서 제목과 시간을 뽑는다. 규칙으로 먼저 뽑고, 안 되면 AI 워커에 맡긴다. 결과를 표로 보여 주고 고치게 한다 |
| YouTube 재생목록 | 무료 강의 | 10초 | 계정 연결과 목록 읽기가 이미 있다. 영상 길이만 더 받아 오면 된다 |
| 강의 사이트 자동 수집 | 인프런, 클래스101 등 | | **하지 않는다.** 로그인 뒤의 화면이고 약관 문제가 있으며 사이트가 바뀔 때마다 깨진다 |
| 사진으로 목차 인식 | 학습지, 교재 | | 뒤로 미룬다. PDF 목차 추출이 이미 있고 OCR은 검증 부담이 크다 |

AI가 뽑은 목차는 **반드시 사용자가 확인한 뒤** 저장한다. PDF 가져오기의 확인 단계와 같은 원칙이다.

## 5. 학습 내용의 기록과 관리

"무엇을 얼마나 했는가"와 "무엇이 남았는가"를 나눠 본다.

**한 것(진도).** 모든 자료에서 같다. "어디까지 했나요?"에 숫자 하나로 답한다. 목차형은 숫자 대신 항목을 고르게 할 수 있다("7강까지"). 시간은 타이머가 채운다. 독서 타이머는 이름만 바꾸면 그대로 학습 타이머가 된다.

**남은 것(기억).** 방금 만든 회상 카드가 여기서 빛을 본다. 강의를 듣고 나서도, 학습지를 풀고 나서도 같은 질문이 나온다. "덮고, 기억나는 것을 적어 보세요." 자료에 묶여 있어서 고칠 것이 거의 없다. 앞면의 "41–60쪽"이 "7–8강"이 될 뿐이다.

**관리.** 자료 상세 화면은 지금의 도서 상세와 같은 뼈대를 쓴다. 진도, 예상 완료일, 기록 이력, 다가오는 일정, 계획 수정, 떠올린 것. 목차형에는 목차 목록이 더해지고 항목마다 완료 표시와 그때 적은 회상이 붙는다.

## 6. 문제 풀이형은 한 걸음 더

학습지와 문제집은 3.1로 일정과 진도까지는 된다. 그런데 이 자료들의 핵심은 **무엇을 틀렸는가**다.

- 기록할 때 선택 입력으로 맞은 수와 틀린 문항 번호를 받는다.
- 틀린 문항은 복습 층의 새 종류(오답)로 들어간다. 앞면은 "수학의 정석 · 142번", 뒷면은 사용자가 적은 틀린 이유다. 문제 자체를 입력하게 하지는 않는다. 책을 펴서 다시 풀게 한다.
- 자료에 단원 태그가 있으면 다른 단원의 오답을 섞어 묻는다. 영상이 말한 교차 연습이 가장 큰 효과를 내는 자리다.

이것은 일정과 별개의 기능이라 3.1을 연 뒤에 따로 판단한다.

## 7. 단계 제안

| 단계 | 내용 | 크기 | 마이그레이션 |
| --- | --- | --- | --- |
| **U1** | 고른 분량형 열기. 단위 이름을 자료에 저장하고, 등록 화면에 "책이 아닌 자료"를 더하고, 진도 저장의 BOOK 문지기를 풀고, 화면의 "쪽"을 단위 이름으로 바꾸고, 통계가 단위별로 집계하게 한다 | 중간 | 있음(작음) |
| **U2** | 독서 타이머와 회상 카드의 문구를 자료 중립으로. 내비게이션의 "독서"를 "기록"으로 | 작음 | 없음 |
| **U3** | 목차형. 엔진이 항목별 시간을 받게 하고, 목차 붙여넣기 등록, 넘침 정책, 배수 학습 | 큼 | 있음 |
| **U4** | YouTube 재생목록을 강의로 가져오기 | 중간 | 없음 |
| **U5** | 오답 기록과 교차 복습 | 중간 | 있음 |

U1과 U2를 마치면 학습지와 문제집, 간이 등록한 강의까지 쓸 수 있다. 여기까지가 "보편 학습 시스템"의 최소 모습이다.

### 칼럼 이름에 대하여

DB의 `start_page`, `end_page`, `total_pages`는 U1에서 **이름을 바꾸지 않기를 권한다.** 뜻은 "시작 단위, 끝 단위, 전체 분량"으로 넓어지지만, 이 칼럼들은 진도 저장과 재계획 SQL 함수, 제약, 테스트 수백 개에 걸쳐 있다. 이름을 바꾸는 마이그레이션은 위험에 비해 얻는 것이 없다. 주석으로 뜻을 밝히고, 웹 코드의 경계에서 `startUnit`으로 옮겨 받는다. 혼란이 실제 버그를 만들기 시작하면 그때 바꾼다.

## 8. 위험

- **입력 비용.** 4절. 등록이 귀찮으면 끝이다. 간이 등록을 언제나 남겨 둔다.
- **추상화가 쓰임을 앞지르는 것.** 혼자 쓰는 제품이다. U3 이후는 실제로 그 자료로 공부할 계획이 있을 때만 연다.
- **책 경험의 퇴보.** 문구를 중립으로 바꾸다 보면 "오늘 20쪽"이 "오늘 20단위"가 되기 쉽다. 단위 이름을 자료마다 저장해 **책은 끝까지 "쪽"이라고 말하게** 한다.
- **정체성.** 넓혀도 흐름은 같아야 한다. 내 속도로 계획하고, 오늘 몫만 하고, 남긴다.
- **넘침 정책의 부작용.** 긴 강의가 많은 과정에서는 매일 넘칠 수 있다. 그때는 계획 화면이 "이 과정은 하루 60분으로는 빠듯해요"라고 미리 말해야 한다. 지금의 충돌 안내가 그 자리다.

## 9. 결정이 필요한 것

1. **지금 실제로 등록하고 싶은 자료가 무엇인가.** 학습지나 문제집이면 U1부터, 길이가 제각각인 강의가 급하면 U3의 우선순위가 올라간다.
2. **강의는 어디서 듣는가.** YouTube 재생목록이면 U4가 가장 편한 길이다. 유료 사이트면 목차 붙여넣기가 주된 길이 된다.
3. **학습지와 문제집에서 맞고 틀린 것을 남기고 싶은가.** 그렇다면 U5를 U3보다 앞에 둘 수 있다.

## 10. 실제 예시 두 개로 다시 보기

받은 예시는 둘이다. 교재 **Basic Grammar in Use**를 공부하는 것, 그리고 인프런 강의 하나를 수강하는 것. 그리고 요구는 "학습일 또는 챕터별로 공부 내용을 등록한다"이다.

### 10.1 두 예시가 알려 준 것

**Basic Grammar in Use는 책이지만 쪽으로 공부하지 않는다.** Unit으로 공부한다. 한 Unit이 두 쪽이고(왼쪽 설명, 오른쪽 연습), 계획도 기록도 "오늘 Unit 12–13"이 자연스럽다. "오늘 24–27쪽"이라고 말하는 사람은 없다. 즉 3절에서 책을 고른 분량형에 넣은 것은 소설에는 맞지만 교재에는 맞지 않는다.

**인프런 강의는 실제로 이렇게 생겼다.** 공개된 강의 소개 페이지에서 확인했다.

| 항목 | 값 |
| --- | --- |
| 전체 | 41강, 7시간 16분, 9개 섹션 |
| 가장 짧은 강의 | 2분 36초 |
| 가장 긴 강의 | 1시간 57분(라이브) |
| 길이가 없는 강의 | 있음("오픈 예정") |
| 목차 | 섹션이 접혀 있고 "모두 펼치기"를 눌러야 강의가 보인다 |

3.2절의 걱정이 그대로 사실이다. 평균 10분이라고 등록하면 2분짜리와 2시간짜리가 같은 무게가 된다. 또 하나 배운 것은 **길이가 없는 항목이 있을 수 있다**는 점이다. 엔진은 항목의 시간이 비어 있어도 돌아야 한다.

페이지를 복사하면 한 강의가 세 줄로 온다("1." 다음 줄에 제목, 그다음 줄에 "20:15"). 사이에 "미리보기" 같은 잡음이 낀다. 섹션 줄에는 제목, 강의 수, 합계 시간이 있다. 규칙으로 뽑을 수 있는 모양이고, **펼치지 않고 복사해도 섹션 단위 정보는 남는다.** 그 경우 섹션을 챕터로 삼고 합계 시간을 쓴다.

주소만 넣으면 자동으로 가져오는 방식이 가장 편하겠지만 하지 않는다는 판단은 그대로다. 남의 서비스를 기계로 긁는 것이고, 페이지 구조가 바뀌면 조용히 깨진다. 붙여넣기는 사용자가 가져온 글을 정리할 뿐이다.

### 10.2 모양이 하나로 합쳐진다

챕터(Unit, 강, 장)를 1급 개념으로 올리면 두 예시는 같은 것이 된다.

| | Basic Grammar in Use | 인프런 강의 |
| --- | --- | --- |
| 챕터 | Unit 1–115 | 1–41강, 9개 섹션 아래 |
| 챕터의 시간 | 모두 같다(배우며 맞춰 간다) | 제각각, 일부는 없음 |
| 등록 | "Unit" × 115를 한 번에 생성 | 목차 붙여넣기 |
| 계획 | 하루 2 Unit | 하루 60분 안에 들어가는 만큼 |
| 진도 | Unit 13까지 | 7강까지 |
| 공부 내용 | Unit별로 남긴다 | 강의별로 남긴다 |

차이는 **챕터마다 시간이 있느냐** 하나뿐이다. 시간이 없으면 같다고 보고, 있으면 그것을 쓴다. 그래서 자료의 모양은 둘이 아니라 이렇게 나뉜다.

- **쪽으로 읽는 자료.** 소설, 교양서. 지금 그대로.
- **챕터로 공부하는 자료.** 교재, 강의, 학습지, 문제집. 새로 여는 것.

DB는 이 모양을 이미 가지고 있다. `resource_units`가 챕터이고(제목, 순서, 예상 시간, 상위 단위, 쪽 범위), `schedule_sessions.unit_id`와 `progress_events.unit_id`가 일정과 기록을 챕터에 잇는다. 세 칼럼 모두 지금은 비어 있다.

### 10.3 "공부 내용을 등록한다"

기록에는 이미 메모 칸(`progress_events.memo`)이 있다. 지금은 기록 창에서 접혀 있어 거의 쓰이지 않는다. 필요한 것은 새 저장소가 아니라 **보이는 자리**다.

- **남기는 자리.** 기록할 때 "무엇을 공부했나요?"가 쪽수와 같은 무게로 보인다. 챕터를 고르고 내용을 적는다. 하루에 여러 챕터를 했으면 챕터마다 따로 적을 수 있다.
- **모아 보는 자리.** 자료 화면에 챕터 목록이 있고, 챕터를 펼치면 그 챕터에서 남긴 내용, 공부한 날짜와 시간, 덮고 떠올린 것이 함께 나온다. 챕터별 보기와 날짜별 보기를 오갈 수 있다. 같은 기록을 두 방향으로 묶어 보는 것이다.
- **메모와 회상은 다르다.** 메모는 공부하며 옮겨 적는 것이고, 회상은 덮은 뒤 꺼내는 것이다. 둘 다 챕터에 붙지만 복습에 나오는 것은 회상뿐이다. 이 구분은 유지한다.

### 10.4 순서를 바꾼다

| 단계 | 내용 | 끝나면 되는 것 |
| --- | --- | --- |
| **C1** | 챕터가 있는 자료. 등록(이름 패턴으로 한 번에 생성, 또는 목차 붙여넣기), 챕터 단위 계획과 진도, 단위 이름, 진도 저장의 BOOK 문지기 풀기. 시간은 모든 챕터가 같다고 본다 | **Basic Grammar in Use를 온전히.** 인프런은 대략적으로 |
| **C2** | 챕터별 공부 내용. 기록 창의 내용 칸, 자료 화면의 챕터 목록과 두 방향 보기, 회상 카드의 앞면을 챕터 이름으로 | 요구하신 "챕터별 등록과 관리" |
| **C3** | 엔진이 챕터마다 다른 시간을 받는다. 넘침 허용, 시간 없는 챕터는 평균으로, 배수 학습 | **인프런을 정확하게** |
| **C4** | 독서 타이머와 내비게이션의 문구를 자료 중립으로 | |
| 뒤 | YouTube 재생목록 가져오기, 오답 기록과 교차 복습 | |

C1과 C2가 요구의 핵심이고 엔진을 고치지 않고 된다. C3는 그 위에 얹는다. C1에서 인프런을 등록해도 쓸 수는 있다. 하루 분량이 고르지 않을 뿐이다.

### 10.5 더 확인할 것

- **Basic Grammar in Use는 어떻게 공부하는가.** Unit을 순서대로 하는가, 필요한 Unit을 골라 하는가. 이 책은 앞에 "어느 Unit을 공부할지 고르는 진단"이 있고 골라서 하라고 권한다. 고르는 방식이면 "k번째까지"가 아니라 **챕터별 완료 표시**가 필요하고, 이것은 C1의 진도 모델을 바꾼다. 가장 먼저 답이 필요한 질문이다.
- **연습 문제의 맞고 틀림을 남길 것인가.** 이 책은 Unit마다 오른쪽이 연습 문제다. 남긴다면 틀린 Unit이 복습에 돌아오는 구조가 자연스럽다.
