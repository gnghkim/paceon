# 학습실 활동 탭 설계

작성일: 2026-09-16 · 기준 커밋: `5e7d18a`

## 1. 목적과 범위

학습실 상세 화면 한 페이지에 보기·말하기·쓰기·질문이 모두 펼쳐져 있어 모바일 스크롤이 길고, 지금 무엇을 하는 화면인지 분명하지 않다. 활동을 탭으로 나눠 **한 번에 한 가지만** 보여준다.

**포함**

- 리스닝 방(`/learn/items/[id]`)에 활동 탭을 도입한다: 영상·메모 / 말하기 / 질문·노트 / 자료.
- 현재 탭을 주소(`?view=`)에 남겨 새로고침·뒤로가기·링크 공유가 동작하게 한다.
- 영상 패널 안의 하위 탭(메모 · 자막·AI 원문 · 시청 구간 · AI 질문)을 없애고 위 탭 한 줄로 흡수한다.
- 탭 전환이 학습 시간 측정과 녹음을 망가뜨리지 않도록 플레이어·마이크의 생명주기를 정한다.
- 946줄인 `learning-room.tsx`에서 탭 본문을 별도 파일로 분리한다.

**제외**

- 라우트 추가·변경. 데이터베이스·API·마이그레이션 변경.
- 기능 삭제. 모든 기능은 유지하며 위치만 바뀐다.
- 스피킹·라이팅 방의 화면 구성 변경. 두 방은 활동이 하나여서 탭을 만들지 않는다.
- 타이머 카드·헤더·전역 내비게이션 변경.

## 2. 현재 구조 (확인한 사실)

- `learning-room.tsx` 946줄이 방 화면 전체를 그린다. 리스닝 방은 위에서부터 이 순서로 쌓인다: 뒤로가기·제목 → 학습 시간 카드(상단 고정, `aria-label="학습 시간"`) → 다른 기기 안내(잠김일 때만) → 플레이어 → 재생 도구(배속·A/B·YouTube에서 열기) → 짧은 구간 쉐도잉 → 영상 제목과 보관 설정(`<details>`) → 하위 탭 → 선택된 하위 패널 → 말하기 연습 → 영상에 관해 질문하기 → 대화와 학습 노트 → 이전 기록 더 보기 → 학습 시간 기록(`<details>`).
- 성격이 다른 텍스트 입력칸이 한 페이지에 셋이다: 구간 메모, 말하기 기준 문장, AI 질문 초안.
- 내용이 하나도 없는 새 방에서 390px 폭 페이지 높이가 3,096px다. 화면 높이 844px 기준 약 3.7화면이다.
- `learning-video-panel.tsx`의 하위 탭은 `메모 / 자막·AI 원문 / 시청 구간` 세 개이며, 옆의 "AI 질문"은 탭이 아니라 `#learning-draft`로 스크롤하는 링크다. 하위 탭을 바꿔도 말하기·질문·노트 섹션은 아래에 그대로 남아 페이지 길이가 줄지 않는다.
- `learningRoomFeatures(kind)`(`learning-areas.ts`)가 영역을 정한다. `video`는 LISTENING만, `writing`은 SPEAKING이 아닐 때, `speech`는 WRITING이 아닐 때, `legacySpeech`는 WRITING만이다.
- `YouTubePlayer`의 생성 효과는 `[videoId]`에만 반응한다. 정리 함수는 `stopPlaybackRef`를 비우고 인터벌을 지운 뒤 플레이어를 파괴하며, **마지막 위치를 보고하지 않는다.**
- `stopPlaybackRef.current`는 `pauseVideo()` 후 `report(true, true)`를 호출해 영상을 멈추고 마지막 위치를 동기화한다. 일시 정지·종료·화면 숨김이 이 경로를 쓴다.
- 방은 15초마다 `HEARTBEAT`를 보내며 `activity`는 "화면이 보이고 마지막 활동이 60초 이내"일 때 참이다. 관측이 끊겨도 60초 뒤 `IDLE`로 자동 정지한다.
- `SpeechPanel`의 정리 함수는 `stopRef.current()`를 호출해 녹음기와 마이크 트랙을 끄고 서버에 정지를 알린다. 미분석 녹음은 `speechDraftStorage`로 기기에 저장되며 다시 마운트될 때 복원된다.
- 방은 `canonical`(`workspaceHref`)과 `pathname`이 다를 때만 `router.replace`를 호출한다. `pathname`에는 쿼리가 포함되지 않는다.
- 순수 로직은 `learning-room-view.ts`에 모여 있고 `tests/learning-room-view.test.mjs`가 `node:test`로 검증한다.

## 3. 화면

### 3.1 탭 구성

타이머 카드 바로 아래에 탭 한 줄을 둔다. 탭은 활동이 둘 이상인 방에만 나타난다. 현재 기준으로 리스닝 방만 해당한다.

| 탭 | `view` 값 | 담기는 것 |
|---|---|---|
| 영상·메모 (기본) | `video` | 플레이어, 재생 도구, 짧은 구간 쉐도잉, 구간 메모 입력과 메모 목록 |
| 말하기 | `speak` | 녹음, 문장 난이도·주제, 기준 문장, 말하기 기록 |
| 질문·노트 | `ask` | AI 질문 입력과 보내기, 대화와 학습 노트, 이전 기록 더 보기 |
| 자료 | `source` | 자막·AI 원문, 시청 구간, 영상 제목과 보관 설정 |

탭 밖에 남는 것: 뒤로가기·제목, 학습 시간 카드, 다른 기기 안내, 오류 알림, 초안 복구 안내, 학습 시간 기록(`<details>`).

영상+메모를 함께 쓰는 사용 방식을 따라 메모는 영상과 같은 탭에 둔다. 말하기와 질문은 영상을 멈추고 하는 작업이라 분리한다.

### 3.2 탭 바

- `<nav aria-label="학습 활동">` 안에 버튼을 두고, 선택된 버튼에 `aria-pressed`를 준다. 저장소 관례상 `aria-current="page"`는 페이지를 옮기는 링크(주 메뉴, 학습 영역 탭)에 쓰고, 화면 안에서 전환만 하는 버튼(영상 하위 탭, 캘린더 보기, 통계 기간)은 `aria-pressed`를 쓴다. 이 탭은 페이지를 옮기지 않으므로 후자를 따른다.
- 390px에서 네 개가 한 줄에 들어가지 않으면 줄바꿈한다. 가로 스크롤은 만들지 않는다.
- 각 버튼 최소 높이 44px를 지킨다.

### 3.3 스피킹·라이팅 방

탭 바를 그리지 않는다. 스피킹은 말하기 하나, 라이팅은 쓰기·질문·노트에 접힌 이전 말하기 기록만 있어 이미 짧다. 이번 변경으로 두 방의 화면은 바뀌지 않는다.

## 4. 주소와 상태

- 현재 탭은 `?view=video|speak|ask|source`로 남긴다. 탭을 바꿀 때 `router.replace`로 기록을 덮어써, 뒤로가기가 탭 이동 하나하나를 되짚지 않고 이전 화면으로 나가게 한다.
- 값이 없거나 알 수 없거나 그 방에 없는 탭이면 기본 탭으로 처리하고 주소를 정리한다. 탭 바가 없는 라이팅 방에 누군가 `?view=speak`를 직접 입력하거나 예전 링크로 들어오는 경우가 여기 해당한다.
- `canonical` 보정은 `pathname`만 비교하므로 쿼리를 지우지 않는다. 구현 중 실제로 확인한다.

## 5. 생명주기 (이 설계의 핵심)

### 5.1 플레이어는 항상 마운트를 유지한다

다른 탭에서는 감싸는 요소에 `hidden` 클래스를 주어 화면에서만 감춘다. 언마운트하면 마지막 위치 보고가 빠지고, 재생 중이었다면 관측이 끊긴 채 최대 60초까지 학습 시간이 더 쌓인다(그 뒤 `IDLE` 자동 정지).

### 5.2 영상 탭을 벗어날 때 영상을 멈춘다

탭이 `video`에서 다른 값으로 바뀌면 기존 `stopPlaybackRef.current()`를 호출한다. 영상이 멈추고 마지막 위치가 동기화된다. 숨긴 채 소리만 나는 상황을 막는다. 다시 영상 탭으로 돌아와 재생을 누르면 정지된 세션도 자동 재개된다(`playResumesPause`).

### 5.3 말하기 패널은 탭을 벗어날 때 언마운트한다

정리 함수가 녹음기와 마이크를 안전하게 끄고 서버에 정지를 알린다. 미분석 녹음은 기기에 남아 돌아올 때 복원된다. 마이크를 쥔 컴포넌트를 보이지 않는 채로 남겨두지 않는다.

### 5.4 녹음 중 탭 이동은 한 번 확인받는다

녹음 중에 다른 탭을 누르면 바로 이동하지 않고 같은 자리에 안내와 버튼 두 개를 보여준다: "녹음을 멈추고 이동" / "계속 녹음". 브라우저 `confirm()`은 쓰지 않는다. 확인 없이 이동해 녹음이 사라지는 일을 막는다.

## 6. 코드 구성

- `apps/web/src/components/learning-room-tabs.tsx` (신규): 탭 바와 탭별 본문 묶음. 방 컴포넌트에서 데이터와 콜백을 받는다.
- `apps/web/src/components/learning-room-view.ts`: 순수 함수 두 개를 추가한다.

```ts
export type LearningRoomTab = 'video' | 'speak' | 'ask' | 'source';
/** 방 종류가 가진 탭 목록. 길이가 1이면 탭 바를 그리지 않는다. */
export function roomTabs(kind: LearningKind): readonly { id: LearningRoomTab; label: string }[];
/** 주소의 view 값을 그 방에서 유효한 탭으로 바꾼다. 모르면 첫 탭. */
export function resolveRoomTab(kind: LearningKind, view: string | null): LearningRoomTab;
```

- `learning-video-panel.tsx`: 하위 탭 상태와 `<nav>`를 걷어내고, 어떤 부분을 그릴지는 위에서 받은 탭 값으로 정한다.
- `learning-room.tsx`: 탭 상태와 5장의 생명주기 조율만 맡고 본문 렌더는 넘긴다. 줄 수가 줄어야 한다.

## 7. 검증

- **단위 테스트**(`tests/learning-room-view.test.mjs`): 종류별 탭 목록, 기본 탭, 알 수 없는 `view`, 그 방에 없는 탭 값 처리.
- **기존 테스트 유지**: 학습 시간·자동 재개 경로는 손대지 않는다. `pnpm test`, `pnpm typecheck`, `pnpm lint`.
- **브라우저 확인**(로컬 dev + 로컬 Supabase, 임시 계정):
  - 390px에서 페이지 높이를 다시 재고 현재 3,096px 대비 얼마나 줄었는지 기록한다. 목표는 1.5화면 이내다.
  - 영상 재생 중 다른 탭으로 이동 → 영상이 멈추는지, DB의 `learning_sessions.elapsed_seconds`가 계속 늘지 않는지 확인한다.
  - 다시 영상 탭 → 재생 → 세션이 재개되는지 확인한다.
  - 녹음 중 탭 이동 → 확인 안내가 뜨고, 멈추고 이동하면 미분석 녹음이 남아 있는지 확인한다.
  - 새로고침·뒤로가기로 탭이 유지·복귀되는지 확인한다.
- **문서**: `docs/LEARNING_ROOM.md`의 화면 설명을 탭 구성에 맞게 고친다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 숨긴 플레이어가 계속 재생돼 시간이 잘못 쌓인다 | 탭을 벗어날 때 `stopPlaybackRef`로 반드시 멈춘다. 브라우저 확인 항목에 포함한다 |
| 녹음 중 탭 이동으로 녹음이 사라진다 | 이동 전 확인 단계를 둔다. 기기 보관 초안 복원도 함께 확인한다 |
| 탭이 늘어 오히려 찾기 어려워진다 | 하위 탭을 없애 탭 층을 하나로 유지한다. 기본 탭은 가장 많이 쓰는 영상·메모다 |
| 리팩터링 중 세션 로직이 깨진다 | 세션·관측 코드는 이동만 하고 수정하지 않는다. 기존 통합 테스트로 확인한다 |
