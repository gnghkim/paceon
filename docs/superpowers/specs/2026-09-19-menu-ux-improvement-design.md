# PC·모바일 메뉴 구성 및 UI/UX 개선안

작성일: 2026-09-19
상태: 구현 완료. 자동 검사와 로컬 브라우저 검증 결과는 [검증 기록](2026-09-19-menu-ux-verification.md)에 정리했다.
목적: 사용자가 기기와 학습 자료 종류에 관계없이 메뉴의 의미를 이해하고, 학습 시작·기록·복습까지 막힘없이 이동하게 한다.

## 1. 배경과 방향

2026-09-19에 로컬 브라우저로 PC 1440×1000, 태블릿 768×1024, 모바일 390×844·320×740 화면을 검토했다. 오늘·영어학습·캘린더·서재·설정·통계를 확인하고 임시 계정의 책·교재·강의 및 영어학습 자료로 주요 문제를 재현했다.

현재 문제의 중심은 화면의 장식보다 **책 중심의 구조에 교재·강의와 영어학습이 추가되며 발생한 범위와 이동 방식의 불일치**다. 차분한 색상, 오늘 중심 진입, 5개 주 메뉴, 기존 학습 데이터와 기록 흐름은 유지한다.

| 검토한 접근 | 장점 | 한계 | 선택 |
| --- | --- | --- | --- |
| 기존 5개 메뉴를 유지하며 기기별 구조와 기능 범위를 정리 | 기존 사용자에게 익숙하며 단계별 적용 가능 | 학습 자료와 영어학습의 구분은 유지됨 | 채택 |
| 모든 학습을 하나의 학습 메뉴로 통합 | 장기적으로 자료 종류를 넓히기 쉬움 | 자료 등록·타이머·기록 구조까지 재설계 필요 | 이번 범위에서 제외 |
| 모바일의 기록 중심 메뉴 유지 | 독서 기록에 빠르게 접근 | 캘린더 접근과 기기 간 일관성 문제가 남음 | 채택하지 않음 |

이 문서에서 구체화한 배치와 문구는 구현 기준안이다. 실사용률을 측정해 최적임을 입증한 결과는 아니다.

## 2. 개선 범위와 우선순위

| 단계 | 우선순위 | 개선 항목 | 완료 결과 |
| --- | --- | --- | --- |
| 1 | P1 | 캘린더의 교재·강의 링크 및 표시 오류 | 어떤 자료든 올바른 이름·단위·상세 화면으로 연결 |
| 1 | P1 | 신규 사용자의 학습 가능 시간 설정 | 책을 먼저 등록하지 않아도 강의 계획 생성 가능 |
| 2 | P2 | PC·모바일 주 메뉴, 기록 버튼, 현재 위치 | 두 기기에서 같은 메뉴와 순서 사용 |
| 2 | P2 | 영어 영역 탭과 이어하기 배치 | 작은 화면에서도 영역 선택을 먼저 발견 |
| 3 | P2 | 서재의 자료 종류·상태·검색·빈 상태 | 조작 이름과 실제 적용 범위 일치 |
| 3 | P2 | 공통 복습의 소속과 진입점 | 독서 복습이 영어학습으로 오인되지 않음 |
| 4 | P2 | 자료 추가 진입점 | 책·교재·강의의 등록 위치를 쉽게 발견 |
| 4 | P3 | 명칭, 설정·계정, 접근성 | 같은 기능은 같은 이름과 상호작용 사용 |

이번 개선은 메뉴와 사용자 흐름에 집중한다. 스케줄러 알고리즘 교체, 데이터베이스 필드명 변경, 통계 집계 범위 확대, 영어·독서 타이머 통합, 새로운 AI 기능, 교재·강의용 보관 기능 신설은 포함하지 않는다. 기존 API의 첫 설정 지원이나 자료 종류별 조회가 불충분한 경우에는 해당 흐름에 필요한 범위만 수정한다.

## 3. 공통 메뉴 구조

PC 사이드바와 모바일 하단 메뉴의 항목·순서를 다음과 같이 맞춘다.

| 순서 | 메뉴 | 경로 | 역할 |
| --- | --- | --- | --- |
| 1 | 오늘 | `/today` | 오늘 할 학습과 공통 복습 |
| 2 | 영어 학습 | `/learn` | 듣기·말하기·쓰기 및 단어장 |
| 3 | 캘린더 | `/calendar` | 날짜별 학습 계획과 일정 |
| 4 | 서재 | `/resources` | 책·교재·강의의 등록 및 관리 |
| 5 | 통계 | `/statistics` | 학습 실적 확인 |

설정과 계정은 보조 메뉴로 유지한다. 복습을 여섯 번째 주 메뉴로 추가하지 않는다.

### 기록 버튼

- 모바일 하단의 `독서` 항목을 `캘린더`로 교체한다.
- `독서 기록`은 PC와 모바일 모두 고정 상단 헤더의 텍스트 버튼으로 제공한다. 모바일 헤더는 로고 → 독서 기록 → 설정 순서로 배치한다.
- 기존 학습 카드와 상세 화면의 기록 행동은 유지한다.
- 이번에는 별도 떠 있는 기록 버튼을 추가하지 않는다. 하단 메뉴·타이머·토스트와의 겹침을 줄이고 전역 기록 행동을 헤더 한 곳에 둔다.
- 현재 전역 기록창은 책만 지원하므로 `학습 기록`으로 이름만 넓히지 않는다. 교재·강의는 기존 챕터 기록 기능을 사용한다.
- 기록창을 닫으면 호출한 버튼으로 포커스를 돌린다. 저장 중 중복 제출 방지와 모바일 키보드 대응을 유지한다.

### 현재 위치

- 책·교재·강의 상세와 모든 자료 추가 화면에서 `서재`가 활성화된다.
- 공통 복습 화면에서는 `오늘`이 활성화된다.
- 설정에서는 주 메뉴를 임의로 선택하지 않고 설정 진입점에 현재 위치를 표시한다.
- 모바일 활성 상태는 색상 외에 배경 또는 표시선을 사용하고 `aria-current`를 유지한다.
- 표시 이름을 바꾸더라도 기존 영어 영역 URL과 마지막 영역 저장값은 유지한다.

## 4. 단계 1 — 막히는 흐름 수정

### 4.1 캘린더의 자료별 표시와 상세 연결

현재 PC 주간·월간 캘린더의 작은 일정 링크는 교재·강의도 도서 경로로 연결한다. 실제로 강의가 `도서 –쪽`으로 표시되고 클릭하면 `책을 찾을 수 없어요`가 나타났다.

변경 기준:

- 책: 책 제목, 페이지 범위, `/resources/[id]`로 연결.
- 교재·강의: 자료 제목과 챕터 제목, 실제 단위 또는 시간, `/resources/materials/[id]`로 연결.
- 페이지 값이 없는 일정에는 `–쪽` 같은 빈 분량을 출력하지 않는다.
- 자료 조회에 실패한 경우 다른 종류의 상세 화면으로 추정 연결하지 않고 `자료 정보를 확인할 수 없어요`를 표시한다.
- 주·월 보기의 작은 일정과 날짜별 상세 카드가 같은 자료를 같은 명칭으로 가리키게 한다.

관련 파일:

- `apps/web/src/components/calendar-view.tsx`
- `apps/web/src/components/session-card.tsx`
- `apps/web/src/lib/workspace-types.ts`
- `apps/web/src/lib/workspace-api.ts`

완료 기준:

- [ ] 책과 강의 일정이 섞인 주·월 보기에서 제목·분량·목적지가 모두 정확하다.
- [ ] 작은 일정 링크와 날짜별 카드가 동일 자료에 대응한다.
- [ ] 모바일 날짜 선택과 기존 책 일정 동작이 유지된다.

### 4.2 첫 학습 가능 시간 설정

현재 새 계정의 강의 계획 생성은 학습 시간이 없다는 안내로 실패하지만, 설정 폼도 첫 책 계획 전에는 숨겨진다.

변경 기준:

- 설정의 `요일별 학습 가능 시간` 입력란은 저장된 규칙이 없어도 표시한다.
- 최초 값은 일곱 요일 모두 빈 값으로 시작한다. 사용자가 선택하지 않은 시간을 자동 저장하지 않는다.
- 빈 요일은 쉬는 날이다. 최소 한 요일에 유효한 시간을 입력해야 저장할 수 있다.
- 최초 저장은 기존 `/api/availability` 경로를 사용한다. 계획이 없는 상태의 저장도 정상 처리되어야 한다.
- 교재·강의 상세에서 시간 미설정 안내에 `학습 시간 설정` 링크를 제공한다.
- 설정 진입 시 해당 자료로 돌아갈 경로를 전달하고 저장 뒤 `계획으로 돌아가기`를 제공한다. 허용되는 복귀 경로는 같은 앱의 자료 상세 경로로 제한하며 외부 URL로 이동시키지 않는다.
- 이미 계획이 있는 사용자는 기존 재계획·충돌 안내를 유지한다. 계획 입력값을 덮어쓰거나 학습 기록을 초기화하지 않는다.

관련 파일:

- `apps/web/src/components/availability-form.tsx`
- `apps/web/src/components/material-detail.tsx`
- `apps/web/src/app/(workspace)/settings/page.tsx`
- `apps/web/src/lib/availability-api.ts`
- `tests/availability-api.test.mjs`
- `tests/unit-materials-api.test.mjs`

완료 기준:

- [ ] 새 계정에서 책 등록 없이 강의 등록 → 시간 설정 → 강의 계획 생성이 가능하다.
- [ ] 모든 요일이 비어 있는 경우 저장 전에 무엇을 입력해야 하는지 안내한다.
- [ ] 기존 시간 수정과 계획 충돌 안내가 유지된다.

## 5. 단계 2 — 기기별 메뉴와 영어학습 배치

### 5.1 전역 메뉴

3절의 공통 메뉴·기록 버튼·현재 위치 규칙을 적용한다. PC·모바일이 하나의 메뉴 정의를 사용하고 경로 판정 규칙도 공유한다.

관련 파일:

- `apps/web/src/components/app-shell.tsx`
- `apps/web/src/components/quick-record.tsx`
- `apps/web/src/components/reading-timer.tsx`
- `apps/web/src/components/ui/button.tsx`

완료 기준:

- [ ] 두 기기의 메뉴 항목과 순서가 같다.
- [ ] 모든 주 화면에서 캘린더와 독서 기록에 직접 접근할 수 있다.
- [ ] 추가·상세·복습의 활성 메뉴가 소속과 일치한다.
- [ ] 320px에서도 헤더의 로고·독서 기록·설정이 겹치지 않는다.

### 5.2 영어 영역 선택과 이어하기

변경 후 화면 순서:

1. 영어 학습 제목.
2. 듣기 / 말하기 / 쓰기 영역 탭.
3. 단어장·공통 복습 보조 링크.
4. 선택한 영역의 시작 행동.
5. 선택한 영역의 이어하기.
6. 저장한 자료와 최근 학습 기록.

- 제목 아래에 이어하기 카드가 끼어들지 않도록 한다.
- 이어하기는 현재 선택 영역에 속한 항목을 우선 표시한다.
- 모바일은 최근 1개와 `이어하기 더 보기`로 나머지를 펼치고 PC는 최대 3개를 표시한다.
- 동일 자료가 이어하기와 저장 목록에 나타날 경우 역할이 드러나는 섹션 제목을 사용한다.
- 마지막 영역 기억과 기존 저장 데이터는 유지한다. 영역 탭 전환만으로 새로운 학습 세션이나 AI 요청을 생성하지 않는다.

- `apps/web/src/components/learning-area-home.tsx`
- `apps/web/src/components/learn-redirect.tsx`
- `tests/learning-areas.test.mjs`

완료 기준:

- [ ] 최근 학습 0개·1개·3개에서 모두 영역 탭이 제목 바로 아래에 있다.
- [ ] 320×740 화면의 첫 진입에서 영역 탭을 스크롤 없이 사용할 수 있다.
- [ ] 현재 영역과 다른 자료가 이어하기의 첫 항목으로 나타나지 않는다.
- [ ] 이전에 사용한 영역으로 진입하는 기능이 유지된다.

## 6. 단계 3 — 서재와 공통 복습

### 6.1 서재의 자료 구분

- 메뉴는 `서재`, 화면 제목은 `내 서재`로 유지한다.
- 설명은 `책·교재·강의를 한곳에서 관리하세요`로 바꾼다.
- 1차 필터는 `전체 / 책 / 교재·강의`로 구분한다.
- `전체`는 보관하지 않은 자료를 종류별로 보여 준다. `책`과 `교재·강의` 섹션에 각각 제목을 붙인다.
- `책`을 선택했을 때 기존 상태 필터 `전체 / 읽는 중 / 완독 / 보관`을 보여 준다.
- `교재·강의`에서는 이번 단계에 기존 비보관 자료 목록을 제공한다. 책의 상태 필터가 이 목록에 적용되는 것처럼 보이지 않게 한다. 새로운 교재·강의 보관 기능을 추가하지 않는다.
- 종류 변경 시 화면에 드러나지 않는 책 상태 필터가 다른 자료를 숨기지 않게 한다.
- 제목·저자 검색은 선택한 종류의 모든 대상에 같은 규칙으로 적용한다. 저자가 없는 자료는 제목으로 검색할 수 있다.
- 자료 자체가 없는 상태, 선택한 종류만 없는 상태, 검색 결과가 없는 상태를 구분한다.
- 강의만 등록된 `전체` 화면에 큰 책 등록 빈 상태를 노출하지 않는다.

관련 파일:

- `apps/web/src/components/book-library.tsx`
- `apps/web/src/components/material-list.tsx`
- `apps/web/src/lib/workspace-api.ts`
- `apps/web/src/lib/workspace-types.ts`

완료 기준:

- [ ] 책만·강의만·혼합 자료에서 종류 필터와 빈 상태가 맞게 동작한다.
- [ ] 교재·강의가 책 상태 필터 때문에 사라지는 상황이 없다.
- [ ] 교재·강의 저자 검색도 검색창의 안내와 일치한다.
- [ ] 보관한 책의 기존 조회 경로가 유지된다.

### 6.2 공통 복습

- 공통 복습의 대표 경로를 `/review`로 둔다.
- 기존 `/learn/review`는 새 경로로 안내하여 북마크와 기존 링크를 유지한다.
- 복습 화면의 공통 상위 메뉴는 `오늘`, 돌아가기 문구는 `오늘로`로 정한다. 브라우저 뒤로 가기는 원래 방문 이력을 따른다.
- 카드에는 독서 회상인지 영어 단어·표현인지 알아볼 수 있는 종류 표시를 제공한다.
- 이번에는 복습 종류별 새 필터나 복습 순서 알고리즘을 추가하지 않는다. 기존 섞어 뽑기와 하루 카드 수를 유지한다.
- 오늘 화면에는 복습할 개수가 0이어도 작은 진입점을 유지한다.
- `0개`만으로 완료를 추정하지 않는다. 저장 자료가 없으면 `복습할 내용을 아직 담지 않았어요`, 예정 항목이 없으면 `오늘 예정된 복습이 없어요`로 표시한다. 실제 완료가 확인되는 경우에만 `오늘 복습 완료`를 사용한다.
- 조회 실패는 예정 항목 없음과 구분하고 다시 불러올 수 있게 한다.
- 영어학습·단어장·독서 상세의 복습 링크도 공통 경로를 가리키게 한다.

관련 파일:

- 새 경로: `apps/web/src/app/(workspace)/review/page.tsx`
- 기존 경로: `apps/web/src/app/(workspace)/learn/review/page.tsx`
- `apps/web/src/components/expression-review.tsx`
- `apps/web/src/components/today-review.tsx`
- `apps/web/src/components/learning-areas-shell.tsx`
- `apps/web/src/components/word-book.tsx`

- `apps/web/src/components/app-shell.tsx`
- `tests/expression-review.test.mjs`
- `tests/expressions-api.test.mjs`

완료 기준:

- [ ] 독서에서 복습에 들어와도 영어학습에 소속된 화면처럼 보이지 않는다.
- [ ] 저장 자료 없음·오늘 예정 없음·복습 가능·조회 실패를 구분한다.
- [ ] 기존 복습 URL이 끊기지 않는다.
- [ ] 카드 선택 순서·평가·다음 복습일 저장이 유지된다.

## 7. 단계 4 — 자료 추가와 명칭 정돈

### 7.1 자료 추가

- PC 사이드바와 서재의 대표 추가 행동을 `자료 추가`로 통일한다.
- `/resources/add`에 자료 종류를 고르는 진입 화면을 추가한다.
- `책`에서는 책 검색·직접 입력과 PDF 가져오기로 연결한다.
- `교재·강의`에서는 기존 직접 등록·목차 입력·링크 가져오기 흐름으로 연결한다.
- PDF는 자료 종류와 같은 수준의 메뉴가 아니라 책을 등록하는 입력 방법으로 설명한다.
- 기존 `/resources/new`, `/resources/import`, `/resources/materials/new`는 계속 사용할 수 있게 유지한다.
- 이미 자료 종류가 명확한 빈 상태에서는 `책 추가`, `교재·강의 추가`로 해당 폼에 직접 진입할 수 있다.
- 영어학습의 YouTube 저장은 기존 듣기 영역에 유지한다. 강의 링크 등록과 같은 데이터 흐름으로 합치지 않는다.

관련 파일:

- 새 경로: `apps/web/src/app/(workspace)/resources/add/page.tsx`
- `apps/web/src/components/app-shell.tsx`
- `apps/web/src/components/book-library.tsx`
- `apps/web/src/components/book-form.tsx`
- `apps/web/src/components/material-new.tsx`
- `apps/web/src/components/pdf-import.tsx`

완료 기준:

- [ ] 사용자가 책·교재·강의의 등록 위치를 하나의 진입점에서 찾을 수 있다.
- [ ] 검색·직접 입력·PDF·링크를 지원하는 기존 등록 흐름이 유지된다.
- [ ] 추가 화면에서도 서재가 활성 메뉴로 표시된다.

### 7.2 표시 문구 규칙

| 대상 | 적용할 이름 |
| --- | --- |
| 영어 주 메뉴·제목 | 영어 학습 |
| 영어 영역 | 듣기 / 말하기 / 쓰기 |
| 영어 시작 행동 | 말하기 시작 / 글쓰기 시작 |
| 서재 메뉴·제목 | 서재 / 내 서재 |
| 전역 책 기록 행동 | 독서 기록 |
| 전역 자료 등록 행동 | 자료 추가 |
| 설정의 시간 배분 | 요일별 학습 가능 시간 |
| 설정의 영어 목표 | 하루 영어 학습 목표 |
| 공통 복습 제목 | 오늘의 복습 |

메뉴를 짧게 쓰고 제목에서 풀어 쓰는 `오늘 → 오늘의 학습`, `캘린더 → 학습 캘린더`, `통계 → 학습 통계`는 유지한다. API 키, 데이터베이스 값, URL, 저장소 키는 표시 문구 변경 대상이 아니다.

### 7.3 설정·계정과 상호작용

- 모바일 헤더의 로그아웃 버튼은 설정의 `계정` 섹션으로 이동한다. 이메일·로그아웃 진행 상태·실패 안내를 함께 제공한다.
- PC 사이드바 하단에는 텍스트 `설정` 진입점을 제공한다. PC의 기존 계정 영역은 유지할 수 있으나 같은 로그아웃 처리와 오류 안내를 사용한다.
- 주요 메뉴와 기록·설정 버튼의 터치 영역을 44px 이상으로 맞춘다. 새 디자인에서는 44~48px를 목표로 하되 모든 버튼 크기를 무조건 일괄 확대하지 않는다.
- 키보드 포커스, 본문 건너뛰기, 아이콘 버튼 이름, 선택 상태를 유지한다.
- safe-area와 실제 하단 메뉴 높이를 반영해 본문·타이머·저장 안내가 가려지지 않게 한다.
- 기존 토큰을 사용해 라이트·다크 화면에서 선택 상태를 확인한다.

## 9. 검증 계획

### 자동 검증

구현한 동작과 연관된 기존 테스트를 먼저 실행한다.

```powershell
node --test tests/availability-api.test.mjs tests/unit-materials-api.test.mjs
node --test tests/learning-areas.test.mjs tests/expression-review.test.mjs tests/expressions-api.test.mjs
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

첫 두 명령은 해당 단계에서 변경된 동작의 검증이다. 전체 명령은 구현 통합 시 실행한다. API 저장 흐름은 로컬 Supabase의 별도 임시 계정으로 실제 저장·재조회까지 확인한다. 데이터베이스 변경이 필요한 것으로 확인되면 해당 DB 검증을 추가하고 문서에 범위를 명시한다.

### 브라우저 확인

| 조건 | 확인 사항 |
| --- | --- |
| 1440×1000 | PC 메뉴, 책·강의 캘린더의 작은 일정 링크, 추가 진입점 |
| 768×1024 | 사이드바 전환 경계, 본문 폭과 설정 폼 |
| 390×844 | 하단 메뉴, 기록 버튼, 서재 필터, 영어 영역 탭 |
| 320×740 | 헤더 겹침, 가로 넘침, 첫 화면의 영역 선택 |
| 자료 없는 새 계정 | 시간 설정, 첫 강의 계획, 자료 추가와 빈 상태 |
| 책만 / 강의만 / 혼합 | 자료별 명칭·검색·필터·상세 경로 |
| 최근 영어학습 0 / 1 / 3개 | 탭 위치, 영역별 이어하기, 더 보기 |
| 복습 없음 / 예정 있음 / 조회 실패 | 진입점 유지와 상태 구분 |
| 라이트·다크 및 키보드 | 선택 상태, 포커스, 기록창 열기·닫기 |
| 기존 상세·복습 북마크 | 이전 URL 호환과 활성 메뉴 |

브라우저에서 작은 뷰포트로 확인한 결과와 실제 모바일 기기에서 확인한 결과는 구분해 기록한다. 실제 키보드·노치·터치 검증을 하지 않았다면 완료 보고에 한계를 명시한다.
