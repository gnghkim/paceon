# 단어장

공부하다 만난 단어를 적어 두면 AI가 한국어 뜻과 짧은 예문을 채운다. 채워진 단어는 다음 날부터 [오늘의 복습](EXPRESSION_REVIEW.md)에 나온다. 사전을 따로 열고 옮겨 적는 일을 없애는 것이 목적이다.

## 공부하다 바로 담기

모르는 단어는 대개 공부하는 도중에 나온다. 듣다가, 읽다가, 쓰다가 만난 단어를
적으려고 화면을 떠나면 하던 것이 끊긴다. 그래서 학습 화면 안에 **단어 담기**를
두었다. 학습 시간 아래, 활동 탭 위에 있으며 리스닝·스피킹·라이팅 모두 같다.

평소에는 단추 하나로 접혀 있다. 누르면 칸이 열리고 바로 입력으로 넘어가므로,
단어를 치고 Enter만 누르면 담긴다. 칸은 그대로 열려 있고 초점도 남아 있어
연달아 담을 수 있다. 뜻은 묻지 않는다.

문장에서 떼어 온 모양은 다듬어 담는다. 앞뒤의 따옴표·괄호와 쉼표·마침표를 떼고,
사이 공백은 한 칸으로 모은다. `"serendipity,"`와 `serendipity`, `put  off`와
`put off`가 서로 다른 항목으로 쌓이면 중복 안내도 걸리지 않기 때문이다. 단어
안쪽의 부호는 건드리지 않아 `don't`와 `well-known`은 그대로 남는다.

담은 단어에는 어느 학습 공간에서 왔는지가 함께 기록된다. 그 공간을 지워도 단어는
남는다. 담는 것은 글쓰기와 같은 학습 행동으로 보아 멈춰 있던 학습 시간을 다시
돌린다. 직접 **일시 정지**를 누른 경우는 깨우지 않는다.

## 단어장에서 넣기

영어학습 화면의 **단어장**, 또는 복습을 마친 화면에서 들어간다(`/learn/words`).

- **단어만 적는 경우**가 기본이다. 넣자마자 카드가 생기고 뜻 자리에 "뜻을 찾고 있어요"가 뜬다. 보통 몇 초 걸린다. 화면은 기다리는 단어가 있는 동안에만 4초마다 결과를 확인하고, 다 채워지면 멈춘다.
- **뜻 직접 쓰기**를 누르면 뜻 칸이 열린다. 적어 넣은 뜻을 그대로 저장하며 AI를 부르지 않는다.
- 같은 단어를 다시 넣으면 **이미 저장한 표현이에요**라고 알린다.

AI 피드백에서 **복습함에 넣기**로 저장하던 길은 그대로 있다. 두 길 모두 같은 표(`learning_expressions`)에 쌓인다. 단어와 표현을 따로 두면 같은 것을 두 번 저장하게 되고 복습도 두 갈래가 되기 때문이다.

## 뜻을 채우는 과정

`lookup_status`가 카드의 상태를 들고 있다.

| 상태 | 뜻 |
| --- | --- |
| `NONE` | 사용자가 직접 적었다. AI를 부르지 않는다. |
| `QUEUED` | 차례를 기다린다. |
| `RUNNING` | Worker가 집어 갔다. 임대가 걸려 있다. |
| `READY` | 뜻과 예문이 들어왔다. |
| `FAILED` | 다섯 번 시도해도 못 채웠다. |

`claim_expression_lookup()`이 한 건씩 집어 가며 2분짜리 임대를 건다. 임대가 끝난 `RUNNING`은 다시 집어 갈 수 있으므로 Worker가 중간에 죽어도 단어가 묶인 채 남지 않는다. `finish_expression_lookup()`은 임대 토큰이 맞을 때만 쓰며, 늦게 도착한 결과는 버린다. 두 함수 모두 `service_role` 전용이고 `authenticated`에게는 실행 권한이 없다.

실패하면 `QUEUED`로 되돌려 다시 시도하고, 다섯 번째부터는 `FAILED`로 둔다. 화면은 그때 뜻을 직접 적어 다시 넣으라고 안내한다. 무한히 다시 부르지 않는다.

뜻이 아직 없는 카드는 복습에 나오지 않는다. 물어볼 답이 없기 때문이다.

## AI에게 보내는 것

`services/ai-worker`의 `VocabWorker`가 처리한다. 경계를 넘는 것은 **사용자가 적은 단어 하나뿐**이다. 행 ID도, 임대 토큰도, 다른 저장 단어도, 학습 기록도 함께 가지 않는다. 테스트가 이를 직접 확인한다.

받는 값은 스키마로 묶는다. 뜻은 1–400자, 예문은 1–3개에 각 1–300자다. 스키마를 벗어나거나 거절·미완성으로 돌아오면 저장하지 않고 실패로 처리한다. 지시문은 입력을 **명령이 아닌 자료**로 다루라고 못박는다. 단어 자리에 명령처럼 보이는 문장이 들어와도 설명할 대상으로만 본다.

실패 사유는 로그로 남기지 않는다. 그 행은 사용자가 적은 단어를 들고 있다.

## 지우기

카드의 휴지통 단추로 지운다. 지운 단어는 복습에 다시 나오지 않는다.

## 아직 아닌 것

- 실패한 카드를 화면에서 바로 다시 시도하는 단추는 없다. 지운 뒤 다시 넣는다.
- 예문을 사용자가 고르거나 고쳐 쓰는 길은 없다.
- `learning_expressions.example`(단수) 칼럼은 `examples`로 옮겨 담은 뒤 더 쓰지 않는다. 지우는 것은 후속 작업이다.

## 검증

- `pnpm test`: 뜻 없이 저장하면 `QUEUED`가 되는 것, 뜻을 적으면 `NONE`인 것, 기다리는 개수, 뜻 없는 카드가 복습에서 빠지는 것. 학습 중 담을 때의 입력 다듬기(앞뒤 부호, 사이 공백, 빈 입력, 길이 한계)와 결과 문구.
- `supabase test db`: 임대와 재집기, 끝난 임대로는 못 쓰는 것, 다섯 번 뒤 `FAILED`, 예문 개수와 길이 한계, 다 채운 카드에는 뜻이 반드시 있는 것, `authenticated`가 두 함수를 부르지 못하는 것.
- `pnpm test:ai:worker`: 단어만 나가는 것, 스키마 밖 응답을 저장하지 않는 것, 제공자 예외가 보고에 새지 않는 것.
- 2026-09-17 실제 확인(학습 중 담기): 리스닝·라이팅 두 화면에서 단어 담기가 보이는 것, `"serendipity,"`가 `serendipity`로 담기는 것, 같은 단어를 다시 담으면 이미 있다고 알리는 것, Enter만으로 연달아 두 개를 담고 초점이 칸에 남는 것, 담은 단어에 학습 공간이 기록되는 것, 담으면 학습 시간이 도는 것, 390px에서 가로 넘침이 없는 것.
- 2026-09-17 실제 확인(단어장): 실제 제공자로 `put off`·`serendipity`의 뜻과 예문 두 개가 채워진 것, 화면에서 단어를 넣으면 "뜻을 찾고 있어요"가 떴다가 결과로 바뀌는 것, 뜻 직접 쓰기로 넣은 단어가 바로 저장되는 것, 390px에서 가로 넘침이 없는 것.
